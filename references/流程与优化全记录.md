## 1. 原始流程（墨纹）摘要

### 1.1 出发点与红线

出发点一句话：**风格本身不受著作权保护，受保护的是具体的画面表达。**
所以只从参考图里学"规律"，画面全部由代码从零画。

| # | 红线 |
|---|---|
| 1 | 参考图只用来统计风格（黑白灰比例、构图比例、线宽、墨溅频率、缩成拼豆后的糊格率），不描图、不取样像素、不做图生图、不拼贴 |
| 2 | 每款画面都由代码从零绘制（样条、几何、程序化纹样），配方代码不读取任何参考图 |
| 3 | 参考图保持私有，不进 git、不进 zip、不外发 |
| 4 | 不碰 IP：动漫/影视/游戏角色、商标、名人肖像、他人签名水印一律不用 |
| 5 | 传统公共母题可以用（骷髅、罗盘、青海波、曼陀罗……），但别照搬某位作者的具体排布 |
| 6 | 每款上线前过原创性核查，超阈值就重画，**不许为了通过去调阈值** |
| 7 | 留证：git 提交时间、固定种子（可逐格复现）、网格源文件、PNG 内嵌作者/版权/时间、原创性报告 |
| 8 | 工程防线不构成法律意见，具体纠纷咨询专业人士 |

### 1.2 十步流程

| 步 | 做什么 | 产出 | 合格标准 |
|---|---|---|---|
| 1 | 收参考图（私有） | `research/*_refs/` | 去重、IP 图已标出 |
| 2 | 风格量化 | `style_dna.json` | 每张图都有指标和标签 |
| 3 | 风格 → 拼豆规则 | 规则表 | 每条规则都有数值并落到代码 |
| 4 | 写配方（原创核心） | 每款一个 `@recipe` 函数 | 能生成、小样好看 |
| 5 | 自查小样 | 原画/拼豆对照图 | 不糊、不断、不飘、铺满 |
| 6 | 编目 | `catalog.py` 一行 | 编号名字唯一、种子固定 |
| 7 | 生成网格 | `grids/MWxxx.txt` | 尺寸/色号/连通/铺满都过 |
| 8 | 原创性核查 | 报告 | `pass: true` + 人工复核最像的几款 |
| 9 | 出交付文件 | 色号图/原画/效果图/总览/目录/zip | 元数据齐全 |
| 10 | 测试、提交、存证 | 提交记录 | 全部测试通过 |

### 1.3 风格 → 拼豆规则（关键数值，**全部沿用**）

| 规则 | 数值 / 做法 |
|---|---|
| 色阶 | 原为 7 档：纸（不放豆）/白/浅灰/中灰/深灰/黑/红 → 现为角色化任意色 |
| 画幅 | S 52×52（1 板）· V 52×104（2 板）· M 78×78（4 板）；设计坐标一律 52 格宽 |
| 栅格化 | 12 倍超采样 + 按色调加权多数表决；黑、白、红权重高，细线小红点不被灰吞掉 |
| 线宽 | 主轮廓 ≥ 1.2 格，细节线 ≥ 1 格；细于 1.35 格自动按"单颗线"落格 |
| 纹样周期 | 重复纹样周期 ≥ 3 格；青海波圈距 ≥ 2 格 |
| 灰阶 | 写实渐变改 2–3 阶色块或 4×4 Bayer 抖动 |
| 墨溅 | 墨点 ≥ 1 格且贴近主体；< 30 格碎块删掉，离主体 ≤ 5 格桥接回来 |
| 外轮廓 | 1 格白豆托底（贴纸感）；1 格闭运算 + 填 ≤ 16 格小洞 |
| 整件 | 四邻连通成一整片，熨好不掉零件 |
| 点睛色 | 每款只用在 1 个焦点上，面积要小 |
| 铺满画面 | 主体包围盒 ≥ 画布 40%，短边 ≥ 45% |
| 孤立单颗 | ≤ 豆子总数 25% |
| 难度 | `score = 颗数/1100 + 孤立单颗/220 + max(0,色数−2)×0.35 + (板数−1)×0.25`；星级 `clip(round(1+score/1.35), 2, 5)` |

### 1.4 原创性核查方法（沿用）

1. 成品网格 → 墨量图（按亮度）→ 裁包围盒 → 拉伸 32×32
2. **NCC**：零均值单位向量余弦相似度（含镜像取大）
3. **dHash**：9×8 差分哈希 64 位，取汉明距离最小值（含镜像）
4. 参考图先转成"照搬版"（直接缩到 52 格再量化），两边同尺度比

阈值是校准出来的：同一张图缩到 44/64 格与 52 格比，NCC 0.854–0.991；不同作品之间 NCC 最高 0.66。
所以判定：与参考图 NCC < 0.75、款与款 NCC < 0.92。

### 1.5 原始踩坑（11 条，**全部保留为硬约束**）

1. 缩图不等于拼豆（直接缩到 52 格，糊格率中位数 62%）
2. 细线和密纹会消失或糊掉
3. 飘在外面的碎点会掉
4. 画面太空不好看
5. 重复款（同题材画成"换个姿势的同一张"）
6. 调色板压缩会并色（小面积红被并成暗红）
7. 改共用引擎会改老作品
8. 种子要固定（只用传入的 rng）
9. 难度要按分布校准
10. 参考图里可能有 IP 或 AI 图
11. 字体路径要能配

### 1.6 原始结论数据（100 款）

- 参考图 19 个文件、去重 18 张、17 张参与统计（一张蜘蛛侠只统计不借鉴）
- 88% 黑白稿；面积约 白 58% / 黑 20% / 深灰 7% / 中灰 7% / 浅灰 8%
- 76% 竖构图，高宽比中位数 1.95
- 直接缩到 52 格，糊格率中位数 62% → **不能缩图，必须按规律重画**
- 配比：S 40 · M 25 · V 35；难度 2★10 / 3★47 / 4★23 / 5★20
- 原创性：与参考图 NCC 最高 0.614（均值 0.351）、dHash 最小 13；款间 NCC 最高 0.752

## 2. 为什么要泛化：原实现的三条硬约束

| 约束 | 后果 | 新方案 |
|---|---|---|
| **色阶写死 7 档**（`PAPER/WHITE/LIGHT/MID/DARK/BLACK/RED`） | 只能做黑白+红的纹身稿，换风格要改 6 个文件 | 角色化配色：`paper/white/light/mid/dark/line/accent/accent2/bg`，颜色写理想十六进制，自动解析成真实色号 |
| **渲染依赖 pycairo**（矢量画布） | Windows 装不上，换机器就跑不起来 | 纯 numpy + Pillow 重写渲染后端 |
| **画面是手写配方**（每款一个 `@recipe` 函数） | 100 款要写 100 个函数，换风格要重写 | 组合式生成：风格包 × 造型 × 构图 × 纹理 × 种子 |

另外原实现用 OpenCV 做形态学/连通域，新实现改用 scipy.ndimage，依赖从 6 个降到 3 个。

## 3. 新架构：四层组合

```
参考图 ──► 风格 DNA（配色/线宽/纹理/构图比例/糊格率）
                │
                ▼
          风格包 JSON ──┐
                         ├─► 配方合成（风格×题材×构图×种子）──► 调色板网格 ──► 拼豆化 ──► 出图
   造型库 75 个 ─────────┤
   构图模板 16 个 ───────┤
   纹理 14 种 ───────────┘
```

**换风格只改 JSON，换题材只加一个函数，换构图只加一个函数。** 这是整套东西能"任意风格"的根本原因。

### 3.1 角色化配色（替代固定 7 档）

| 角色 | 作用 | 必需 |
|---|---|---|
| `line` | 描边、轮廓、深色细节 | **是** |
| `white` | 高光、眼白、留白、贴纸白边 | 建议 |
| `light` / `mid` / `dark` | 主体亮面/中间调/暗面 | 建议 |
| `accent` / `accent2` | 点睛色（每款只用一处） | 可选 |
| `bg` | 满底铺色时的底色 | `bg=fill` 时必需 |

解析流程：理想色 → CIEDE2000 在 MARD 色卡里找最近的真实色号 → 输出 ΔE 误差。
同一个色号被两个角色抢用时自动换次优，避免"两种灰其实是同一颗豆"。
角色缺失时按语义链回退（`accent→line→dark`），所以只有 2 个色的风格包也能跑。

### 3.2 风格包（14 个内置）

`ink_tattoo` 墨纹 · `kawaii_pastel` 马卡龙萌系 · `pop_art` 波普 · `pixel_retro` 像素复古 ·
`mandala_gold` 曼陀罗金 · `ukiyoe` 和风 · `lowpoly` 低多边 · `neon_cyber` 赛博霓虹 ·
`botanical` 植物线描 · `stained_glass` 彩窗 · `chinese_ink` 国风水墨 ·
`nordic_tribal` 北欧部落 · `sunset_warm` 落日渐变 · `anime_cel` 日系赛璐璐

一个风格包约 80 行 JSON，控制：配色、底色模式、线宽、明暗角色、纹理（含随机池）、
画幅配比、允许的构图、默认题材、点缀策略、难度系数、自动匹配用的四个统计目标。

### 3.4 构图模板（16 个）

`tile` 纹样铺贴 · `sticker` 贴纸 · `card` 卡片 · `corner` 角饰 · `horizon` 地平线 ·
**`scene` 场景**

模板自己负责：底色、边框、主体摆位、竖幅的下方装饰。**关键约束：主体必须贴住边框/地面**，

### 3.5 纹理库（14 种）

`solid` `stipple` `hatch` `cross` `dots` `scales` `seigaiha` `waves` `checker` `halftone`
`confetti` `contour` `weave` `gradient`

风格包可以给一个 `texture_pool` 列表，每款随机挑一种——同一风格下也有变化，避免"一套图长得一样"。
口诀：**线越细，纹理越要粗**；细线 + 密网点 = 糊。

## 4. 引擎重写（cairo → numpy + Pillow）

### 4.1 渲染管线

```
显示列表（poly/stroke/tapered/circle/ring/rect/compound/clip/pixels）
   │
   ├─► 网格路径：8 倍超采样 → PIL 多边形逐形状栅格化 → 每格按"加权多数表决"落一颗豆
   │
   └─► 原画路径：设计坐标系 32 px/格 渲染 → 2 倍降采样（BOX）→ 抗锯齿原画
```

- **加权表决**：`line` 1.55、`accent` 1.60、`white` 1.50、`paper` 0.80。
  线和小红点权重高，所以半格墨也算墨、一颗红豆不会被灰吞掉。
- **偏移轮廓描边**：粗线不逐段画，而是算"中心线两侧各偏移 w/2 的闭合多边形"再填充。
  （原因见 10 节 O2）

### 4.2 断线与糊的治理

| 机制 | 做法 |
|---|---|
| 单颗线落格 | 网格里宽度 < 1.35 格的线，用 Bresenham 式单颗线落格，并去掉 L 形拐角多余格 → 不会断、不会变双线 |
| 单颗豆 | 半径 < 0.8 格的圆点直接落成 1 颗豆 |
| 细段补线 | 锥形笔刷的尖端细于 1.35 格时，沿中心线补一条单颗线，尖端不会断 |
| 格级效果 | 点刺/抖动在多数表决之后执行，只落在纸色和白豆上，不会盖掉黑线 |

### 4.3 性能

单款约 1.5–2.5 秒（含色号图 + 原画 + 效果图三张 PNG）。12 款全套约 24 秒。

## 5. 参考图分析（analyze）

### 5.1 量化指标

| 指标 | 说明 |
|---|---|
| 主色 | k-means（k=8）→ 色值 + 面积占比 |
| 明暗分布 | 5 档亮度面积占比 |
| 饱和度 / 对比度 | 彩色度、亮度标准差 |
| 边缘密度 | Sobel 梯度超过"相对对比度固定阈值"的像素比例 |
| 线宽 | 边缘像素到非边缘的平均距离 ×2 |
| 对称性 | 左右镜像相关系数 |
| 画幅 | 高宽比 → 推荐 S/M/V 配比 |
| 背景 | 四边中位色 + 占比 → 判断纸底还是满底 |
| **糊格率** | 直接缩到 52 格后，3×3 邻域亮度跳变超过 45 的格子比例 → 越高越说明不能缩图 |

### 5.2 配色双模式（重要优化）

| 参考图类型 | 判定 | 角色分配 |
|---|---|---|
| 黑白稿 / 线描 | 饱和低 | 亮度阶梯：line 0.04 / dark 0.22 / mid 0.48 / light 0.72 / white 0.97，缺档插值补 |
| 彩色稿 / 照片 / 插画 | 饱和高 | **按"面积 × 色相差异"挑 3 个真正不同的颜色**，避免一路灰下去 |

### 5.3 照片识别

`photo_like` = 边缘密度 < 0.10 且饱和度 > 0.15。命中后自动：
- 底色改 `fill`（满底铺色，照片不留白边）
- 纹理推荐 `gradient`（照片边缘柔和，点刺会脏）
- 地面角色用 `mid`（水面/地面），不是死黑

## 6. 拼豆化（beadify）

按顺序执行，全部沿用原规则：

1. 墨迹 1 格闭运算（补断点）
2. 填 ≤ 16 格的小洞（大块留白保持镂空）
3. 外扩 1 格作白豆托底（贴纸感）
4. 循环处理碎块：< 30 格删掉；离主体 ≤ 5 格用四邻桥接并进来，直到只剩一整片
5. 剪影内没上色的格子补白豆
6. 统计：颗数、色数、孤立单颗、板数、成品尺寸、难度星级、预计工时

**新增兜底**：如果整理后豆子少于原来的 55%（说明主体被当成碎块删了），
自动放宽桥接距离到 16 格、最小碎块降到 14 格重跑一次。

## 7. 原创性核查

方法与阈值沿用第 1.4 节，但**判定规则改了一处**（原因见 10 节 O20）：

| 项 | 阈值 |
|---|---|
| 与任何参考图 NCC | < 0.75 |
| 与任何参考图 dHash 距离 | ≥ 10（**仅当 NCC ≥ 0.60 时才参与判定**） |
| 款与款之间 NCC | < 0.92 |

判定逻辑：`太像 = NCC ≥ 0.75 或 (dHash < 10 且 NCC ≥ 0.60)`。
理由：拼豆图很稀疏，两件完全不同的作品也可能落在同一档哈希上；而"照搬"的 NCC 一定 ≥ 0.85。
数值通过后仍要人工复核 `nearest_ref` 最高的几款。

| `原创性报告.md` / `.json` | 与参考图、款与款的相似度 |
| `说明.txt` / `系列名_全套.zip` | 使用说明 / 全套打包（**不含参考图**） |

所有 PNG 内嵌 Title / Author / Copyright / Description / CreationTime 元数据，可举证。
色号图用"关键色锁定"的调色板压缩（`quantize_keep`），避免小面积点缀色被并掉。

## 9. 三类素材的打法

| 素材 | 能不能做 | 怎么做 |
|---|---|---|
| 动物 / 植物 / 天体 / 器物 / 符号 | ✅ 完全能 | 造型库直接对应，随便挑构图 |
| **风景照片** | ✅ 能 | `scene` 构图（天空→远山两层→主体→地面/水面+前景）+ `hill/forest/lake/house/boat/lighthouse` |
| **人物照片** | ⚠️ 只能做原创头像 | `bust`/`chibi` 出原创形象，**不还原相貌**（肖像权） |
| **漫画 / 动漫角色** | ⚠️ 只能做同风格原创角色 | 用该作品的画风画全新角色，**不复刻具体角色**（IP 红线） |

**边界要说清楚**：这套系统"风格任意"，但"题材有词汇表"（75 个造型）。
库外的题材（某款车、某栋楼、某个具体角色）要么用近似造型，要么新写一个造型（约 20 行）。
另外它出的是"同风格的新作品"，不是"把这张照片原样转成图纸"——后者是 `pindou-gongzi` 的活。

## 10. 优化清单（v1 → v2 全部改动）

| # | 问题 | 原因 | 改法 | 验证 |
|---|---|---|---|---|
| O1 | 换机器跑不起来 | 渲染依赖 pycairo + OpenCV | 纯 numpy + Pillow + scipy 重写渲染与形态学 | 本机（无 cairo/opencv）跑通 |
| O2 | 粗线边缘有 1px 白色接缝 | PIL 逐段画线，相邻段之间漏缝 | 改"偏移轮廓多边形 + 奇偶填充"一次成形 | 放大 4 倍检查无缝 |
| O3 | 原画边缘有毛刺 | LANCZOS 降采样在高对比边缘振铃 | 改 BOX（面积平均）降采样 | 圆环边缘干净 |
| O4 | 原画外面一圈白噪点 | 白豆托底被画成小圆点 | 亮度 > 238 的点不画 | 纸底干净 |
| O5 | 只能做黑白红 | 色阶写死 7 档 | 角色化配色（9 个角色，可缺省可回退） | 14 个风格包 |
| O6 | 图纸色号买不到 | 直接写十六进制 | 理想色 → CIEDE2000 匹配真实 MARD 色号 + ΔE 报告 | 全部色号在 291 色卡内 |
| O7 | 两种灰其实是同一颗豆 | 两个角色匹配到同一色号 | 抢占时自动取次优 | 色数统计不再虚高 |
| O8 | 换题材要写新配方 | 每款一个手写函数 | 参数化造型库（0→75），`@motif` 装饰器自动注册 | 75 个造型对照表 |
| O9 | 构图只有几种 | 手写配方自带构图 | 构图模板库（0→16），主体摆位统一由模板管 | 16 个模板 |
| O10 | 同风格下每款长得像 | 纹理固定 | 14 种纹理 + `texture_pool` 每款随机 | 同套内纹理有变化 |
| O11 | 有些款主体特别小 | 造型尺寸与画布不匹配 | 按造型包围盒自动放大一次（环形构图限 1.18 倍防顶穿） | 主体占位率提升 |
| O12 | 主体飘着、熨完掉件 | 主体没贴住边框/地面，被当碎块删 | 模板改为"主体贴住边框/地面"；竖幅加竖向装饰 | 112 款全部一整片 |
| O13 | 偶尔整款变空 | 碎块清理把主体删了 | 豆子少于原来 55% 时放宽桥接距离重跑 | 0 空款 |
| O14 | 边缘密度恒为 0.12 | 阈值取了 88 分位数，比例天然固定 | 改"相对对比度的固定阈值"（0.3×P99.5） | 不同图有区分度 |
| O15 | 彩色图配色糊成灰 | 只按亮度分配角色 | 双模式：黑白走亮度阶梯，彩色按色相差异挑色 | 风景系列有 4 个真色 |
| O16 | 照片被做成"白底图标" | 背景判定只看占比 | `photo_like` 判定 → 满底 + 渐变纹理 + 地面用 mid | 风景系列像照片 |
| O17 | 风景变成一枚徽章 | 没有分层构图 | 新增 `scene` 模板（四层：天空/远山两层/主体/地面+前景） | 10 款风景系列 |
| O18 | 不能做人物/角色 | 没有人物造型 | 新增 `chibi`/`bust` + `anime_cel` 风格包 | 8 款角色系列 |
| O19 | 同题材同构图出重复款 | 构图只按顺序轮，不查重 | 同一 (题材,构图) 组合全局唯一 | 款间 NCC 0.913 → 0.79 |
| O20 | 原创性报告误判"未通过" | dHash 单指标在稀疏图上误报 | 改组合判定（NCC 优先，dHash 仅在 NCC ≥ 0.60 时参与） | 12 款系列通过 |

| O22 | 缺角色时程序崩溃 | `palette.index` 直接抛异常 | 语义链回退（accent→line→dark…） | 2 色风格包也能跑 |

## 12. 已知限制与下一步

**限制**
1. 题材是封闭词汇表（75 个）。库外题材要加造型，不是"丢张图就会"。
2. 人物只能做原创形象，不做相貌还原。
3. 竖幅里扁平题材（鲸、海龟、莲花）容易显空，需要换构图或换题材。
4. 复杂场景（多层建筑、人群、车辆）目前做不到，需要专门的构图与造型。
5. 效果图是模拟，不是真实熨烫照片。

**下一步（按价值排序）**
1. 按销量反馈补造型：先补客户最常问的题材（十二生肖、星座、城市地标、宠物品种）
2. 加"场景道具"：桥、栅栏、路、船坞、招牌，让风景更像景
3. 加"文字/数字"造型：生日、姓名首字母（拼豆礼品刚需）
4. 风格包继续扩：国潮、昭和复古、Y2K、莫兰迪、铅笔素描
5. PDF 图纸（A4 分页 + 分区编号），方便打印

### D. 新增踩坑（v2 追加）

1. **双重缩放**：`T(pts,cx,cy,s)` 之后坐标里又乘 `s`，花朵造型一度把整张画布糊满。
   约定：局部坐标一律 [-1,1]，缩放只在 `T()` 里做一次。
2. **主体飘着被删**：模板摆位不贴边框，`finalize` 就当碎块清掉。模板必须保证主体贴住。
3. **竖幅空白**：52×104 用圆形构图会上下大片空，必须改椭圆 + 下方竖向装饰。
4. **dHash 误报**：稀疏图哈希碰撞率高，单看 dHash 会冤枉好作品，要和 NCC 一起判。
5. **同题材同构图 = 重复款**：排方案时必须做组合查重，否则一套里会出现两张几乎一样的。
6. **白豆托底别画进原画**：纸底上看不见，只会变成一圈噪点。
7. **加造型时先跑 audit**：75 个造型一起排出来看，糊/断/空一眼就能挑出来。
